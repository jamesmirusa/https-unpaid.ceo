## Final review — fixed (each by a test that failed first)

- #1 (Critical) an account change during a run left the old player's CloudSync live, so the device career could be written into the newly signed-in account's cloud — CloudSync binds writes to the player it pulled for; run screens subscribe AccountChanged; OnAccountChanged drops _sync before any await — Writes_stop_when_the_player_changes RED→GREEN, suite PlayMode 96/96.
- #2 the cloud could be overwritten after it won (a month finished before the restart, or a failed adopt) or by a device behind another — writes stay off after UseCloud until a new pull; each debounced write re-reads the cloud and never replaces a longer game — After_the_cloud_wins_nothing_is_written_until_a_new_pull, A_push_never_replaces_a_longer_cloud_game RED→GREEN, suite PlayMode 96/96.
- #3 a resent challenge run or a failed board write spent an attempt — verify, then board, then count; counted runs are the state hashes in challenge_runs_<week>, a known hash answers Ok without counting — A_resent_challenge_run_counts_once, A_failed_board_write_does_not_spend_an_attempt RED→GREEN, server 17/17.
- #4 challenge/duel replays accepted scenes, storylet choices, quizzes and chapter moves the client never plays (a modified client could roll scenes and keep the lucky ones) — ReplayStrict accepts only endMonth and takeLoan in scenario runs — Scenario_runs_accept_only_month_plans_and_loans RED→GREEN, server 17/17, EditMode 286/286.
- #5 a career ahead of real time was refused outright, so an honest player who played offline before the first online visit never ranked — one day of pacing slack, and a longer career ranks its net worth as it stood when the first month past the limit began (SubmitResult.Paced, no market board) — Careers_ahead_of_real_time_rank_their_paced_months RED→GREEN, server 17/17.
- #7 every Cloud Code failure read as "offline", so one entry the server failed on blocked the queue forever, and queued runs could be sent under another account — UgsOnlineServices.ErrorFor (transport, timeout, unavailable, rate limit, token → offline; other service answers → server_error); the queue retries server_error on up to 5 flushes then gives it up, never stops behind it, and sends only the current player's entries (or ones played signed out) — Server_failures_are_told_apart_from_being_offline, A_failing_run_is_retried_without_blocking_the_others, Entries_wait_for_the_player_who_played_them RED→GREEN, suite PlayMode 96/96.
- #8 unbounded duel creation could flood any player's duel list — 10 duels created per player per UTC day (duels_created_<day>), opponent id must match ^[A-Za-z0-9_-]{1,64}\z — Duel_creation_is_capped_per_day RED→GREEN, server 17/17.

## Deferred minors

- count endMonth entries before replaying a huge log, to reject oversize submissions cheaply.
- no trailing debounced cloud flush on WebGL (browser pause/quit events are unreliable), so up to 20 s of progress can miss the cloud.
- the queue stores a second full copy of the career log, halving PlayerPrefs headroom on WebGL.
- one run slot — starting the other run kind overwrites a half-played run.
- the grace hour barely helps, because Play labels a run with Hello's week.
- queued challenge results are never shown and never grant the badge.
- in RunMode, Reset does nothing and challenging a friend does not start the duel.
- ranking refresh costs — Hello on every refresh, ListDuels reads up to 50 duel entities.
